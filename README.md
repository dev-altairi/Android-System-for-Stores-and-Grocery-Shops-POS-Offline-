# خطة ترقية وتطوير نظام POS Offline Pro (المرحلة الثانية)

خطة معمارية تفصيلية لتطوير 3 محاور أساسية تم اختيارها لرفع كفاءة التطبيق الميدانية وتخصيصه بالكامل للبقالة:
1. **نظام المرتجعات واسترداد الفواتير (Sales Returns & Refunds)** مع إعادة الكميات آلياً للمخزون وتسوية الصندوق وحسابات العملاء.
2. **النسخ الاحتياطي المحلي وتصدير التقارير بصيغة CSV / Excel** لحماية البيانات ومشاركتها بسهولة دون إنترنت.
3. **شاشة إعدادات المتجر المخصصة (Store & Receipt Settings)** للتحكم في اسم المحل، العنوان، أرقام التواصل، رسالة تذييل الفاتورة، وتفضيلات النظام.

---

## مراجعة المستخدم والقرارات المؤكدة (User Review & Confirmed Decisions)

> [!IMPORTANT]

> - **الأولوية الأولى**: إضافة النسخ الاحتياطي المحلي الآمن وتصدير التقارير والمبيعات إلى ملفات CSV/إكسل متوافقة مع الجوال.
> - **الأولوية الميدانية للكاشير**: نظام متكامل لإرجاع الفواتير أو أصناف محددة، مع خيار إرجاع نقدي من الصندوق أو خصم من دين العميل وإرجاع فوري للمخزون.
> - **التخصيص والإعدادات**: شاشة إعدادات متكاملة تتيح لمالك المتجر تعديل اسم المتجر، الهاتف، العنوان، ورسالة شكر الفاتورة، وتنعكس مباشرة على الإيصالات الحرارية وشاشات التطبيق.

---

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **الوظيفة المضافة**:
  - تمكين الكاشير من البحث في الفواتير السابقة والضغط على "استرجاع الفاتورة" أو اختيار أصناف معينة لإرجاعها؛ مما يُعيد الكميات إلى جدول المخزون فوراً، ويسجل حركة صرف نقدية بالصندوق أو يُخفض رصيد دين العميل إن كانت الفاتورة آجلة.
  - حماية بيانات المتجر بنقرة واحدة من خلال إنشاء ملف نسخة احتياطية محلية (JSON/SQLite Backup) يمكن حفظه أو مشاركته عبر واتساب/البلوتوث واستعادته عند الحاجة.
  - تصدير تقارير المبيعات والأصناف وحسابات الديون إلى جداول (CSV) لفتحها في برنامج Excel أو مشاركتها مع المحاسب.
  - إمكانية تخصيص هوية المتجر (اسم البقالة، العنوان، الهاتف، تذييل الفاتورة) وتخزينها محلياً دون الحاجة لإعادة كتابة الأكواد.

---

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### مسارات المستخدم الإضافية (New User Flows)

1. **مسار استرجاع الفواتير (Sales Return Flow)**:
   - يفتح الكاشير شاشة الفواتير السابقة أو يبحث برقم الفاتورة (مثال: `INV-2610-01`).
   - يظهر زر "استرجاع / مرتجع" مع نافذة مخصصة تتيح استرجاع كامل الفاتورة أو تحديد كميات مرتجعة.
   - يحدد الكاشير طريقة رد المبلغ: نقداً من الصندوق، أو تسوية رصيد العميل الآجل.
   - يصدر التطبيق "إشعار دائن / إيصال مرتجع" قابل للطباعة والمشاركة، ويحدّث المخزون والصندوق فوراً.

2. **مسار النسخ الاحتياطي والتصدير (Backup & Excel Export Flow)**:
   - في تبويب الإعدادات والتقارير، يتوفر قسمان رئيسيان:
     - **النسخ الاحتياطي**: زر "إنشاء نسخة احتياطية الآن" يولّد ملفاً شاملاً لكافة المنتجات، الفواتير، ديون العملاء، وحركات الصندوق مع خيار فوري للمشاركة أو الحفظ بجهاز الهاتف، وزر "استعادة نسخة سابقة".
     - **تصدير التقارير (Excel/CSV)**: زر تصدير مبيعات اليوم، تصدير قائمة المنتجات والمخزون، وتصدير كشف ديون العملاء كملفات CSV جاهزة للمعاينة.

3. **شاشة إعدادات المتجر (Store Settings Tab/Dialog)**:
   - شاشة مريحة تحتوي على:
     - اسم المتجر (الافتراضي: بقالة الأمانة والتجارة الحديثة).
     - رقم الهاتف / الجوال.
     - العنوان / المدينة.
     - نص الترحيب ورسالة الشكر أسفل الفاتورة الحرارية.
     - زر حفظ التغييرات وانعكاسها الفوري على شريط التطبيق العلوي والفواتير المطبوعة.

## 3. القرارات التقنية والمفاضلات (Key Product Decisions)

1. **إدارة إعدادات المتجر عبر كيان Room محلي أو DataStore**:
   - *الخيار المعتمد*: كيان `StoreProfile` ضمن قاعدة بيانات `Room` المحلية.
   - *السبب*: يحافظ على تناسق قاعدة البيانات، ويسمح بتضمين إعدادات المتجر ضمن ملف النسخ الاحتياطي الموحد واستعادتها دون انقطاع.
2. **هيكلة حركة المرتجعات في سجل الصندوق والمخزون**:
   - *الخيار المعتمد*: تسجيل المرتجع كنوع فاتورة `RETURN` أو `SaleOrder.isReturned` مع تسجيل حركة صندوق من نوع `REFUND`، وإعادة زيادة كمية المخزون عبر استعلام `deductStock(id, -qty)`.
   - *السبب*: دقة الحسابات المحاسبية وعدم فقدان تاريخ الفاتورة الأصلية.
3. **صيغة تصدير التقارير والنسخ الاحتياطي**:
   - *الخيار المعتمد*: تصدير CSV ذو ترميز UTF-8 مع BOM لضمان قراءة النصوص العربية بشكل صحيح داخل برنامج Microsoft Excel، وتصدير ملف JSON متكامل للنسخ الاحتياطي والاستعادة السريعة.

## 4. البنية البرمجية ونموذج البيانات (Technical Architecture)

### مخطط تدفق العمليات الإضافية (Updated Data & Action Flow)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        POS UI Layer (Compose)                          │
├──────────────────┬───────────────────┬─────────────────────────────────┤
│ Return Invoice   │ Store Settings    │ Backup & CSV Export Actions     │
│ - Select items   │ - Store Name      │ - Generate Backup JSON          │
│ - Stock restore  │ - Receipt Footer  │ - Restore Backup                │
│ - Cash refund    │ - Contact info    │ - Export Sales & Debt to CSV    │
└─────────┬────────┴─────────┬─────────┴────────────────┬────────────────┘
          │                  │                          │
          ▼                  ▼                          ▼
┌────────────────────────────────────────────────────────────────────────┐
│                      POS ViewModel & StateFlow                         │
│  handleOrderReturn(), updateStoreProfile(), exportCsv(), backupData()  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │

┌────────────────────────────────────────────────────────────────────────┐
│                      PosRepository Layer                               │
│  - Atomic Return Transactions (Stock rollback + Cash outflow)          │

│  - StoreProfileDao persistence                                         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                       Room Local Database                              │
│  [Products]  [SaleOrders & Returns]  [Customers]  [StoreProfile]       │
└────────────────────────────────────────────────────────────────────────┘
```

### الكيانات والتحديثات المقترحة (Proposed Entity Changes)

1. **`StoreProfile` (جديد)**:
   - `id`: Int = 1 (سجل وحيد)
   - `storeName`: String
   - `phone`: String
   - `address`: String
   - `receiptFooter`: String
2. **تحديث `SaleOrder`**:
   - إضافة خاصية `isReturned`: Boolean = false
   - إضافة خاصية `returnReason`: String = ""
3. **تحديث `CashTransaction`**:
   - دعم نوع `REFUND` للمبالغ المعادة للعملاء عند استرجاع الفواتير.

## 5. خطوات التنفيذ المعتمدة (Implementation Steps)

1. **إضافة كيان `StoreProfile` وتحديث قاعدة بيانات Room**:
   - إنشاء `StoreProfile` و`StoreProfileDao` في طبقة البيانات.
   - تحديث `AppDatabase` ومستودع البيانات `PosRepository` لتحميل وحفظ إعدادات المتجر.
2. **تطوير ميزة استرجاع الفواتير (Refunds / Returns)**:
   - كتابة دالة `returnOrder(orderId, refundType, reason)` في المستودع:
     - تحديث الفاتورة إلى مرتجعة.
     - استعادة كميات الأصناف في المخزون.
     - تسجيل حركة صرف نقدية بالصندوق أو تخفيض دين العميل.
   - إضافة زر وإجراء "استرجاع الفاتورة" في نافذة الفواتير السابقة مع إشعار نجاح فوري.
3. **تطوير محرك النسخ الاحتياطي وتصدير التقارير (CSV / Backup Engine)**:
   - محرك توليد ملفات CSV للمبيعات والمخزون وحسابات الديون ومشاركتها عبر Android Sharesheet.
   - تصدير نسخة احتياطية شاملة بصيغة JSON مع خيار الاستعادة بضغطة زر.
4. **بناء شاشة وتفضيلات الإعدادات (Store Settings Screen)**:
   - واجهة مخصصة لتعديل اسم البقالة، العنوان، الهاتف، ورسالة الإيصال الحراري.
   - ربط الفاتورة الحرارية والشريط العلوي بالبيانات المعدلة ديناميكياً.
5. **التحقق والاختبار (Verification)**:
   - فحص واختبار التجميع بـ `compile_applet` وتشغيل الاختبارات لضمان أعلى استقرار.
