# نظام كاشير ونقاط البيع السريع للمتاجر والبقالات (POS Offline Pro)

تطبيق أندرويد متكامل ومستقل 100% يعمل بدون إنترنت، مخصص لإدارة نقاط البيع السريعة، المخزون، حسابات الديون والعملاء، وحركة الخزينة والتقارير المالية بالريال اليمني مع دعم مسح الباركود بالكاميرا وإصدار الإيصالات الحرارية.

---

## مراجعة المستخدم والقرارات المؤكدة (User Review & Critical Decisions)

> [!IMPORTANT]
> - **طبيعة النشاط التجاري**: بقالة ومتجر تجزئة عام (سريعة البيع، تصنيفات استهلاكية، متابعة الصلاحيات ونفاد الكميات).
> - **العملة المعتمدة**: الريال اليمني (**ر.ي** / YER) مع دعم الخصومات وطرق الدفع (نقدي، آجل/دين، تحويل).
> - **إدخال المنتجات في الكاشير**: الجمع بين مسح الباركود المباشر عبر الكاميرا وشبكة المنتجات السريعة المصنفة والبحث الفوري.
> - **العمل بدون إنترنت (100% Offline)**: استخدام مكتبة **Room Database** المحلية لتخزين آمن، فوري، وموثوق دون الحاجة لأي خادم سحابي.

---

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **الوظيفة الأساسية**: نظام كاشير ونقاط بيع وإدارة متجر في متناول اليد. يمكن صاحب البقالة أو الكاشير من إضافة المنتجات بباركود أو بدون، إتمام عمليات البيع بأقل من ثانيتين، طباعة ومشاركة فواتير حرارية احترافية، تتبع ديون الزبائن والموردين، ومراقبة أرباح الصندوق الصافية لحظة بلحظة.
- **الفئة المستهدفة**: أصحاب البقالات، السوبرماركت، متاجر التجزئة ومحلات التموينات الذين يحتاجون حلاً موثوقاً وسريعاً لا يتعطل بانقطاع الكهرباء أو الإنترنت.
- **القيمة المضافة**: التخلص من الدفاتر الورقية، سرعة المحاسبة، منع التلاعب بالأسعار والمخزون، ومعرفة المنتجات الأكثر ربحية والمنتجات منتهية الصلاحية بلمسة واحدة.

---

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### مسارات المستخدم الرئيسية (Key User Flows)
1. **شاشة نقطة البيع (POS)**:
   - عرض فئات سريعة (الكل، معلبات، ألبان وأجبان، مشروبات، بسكويتات وحلويات، خضروات، منظفات).
   - النقر على أي منتج يضيفه مباشرة إلى السلة العائمة مع عداد كميات فوري.
   - زر مسح الباركود بالكاميرا يتعرف فوراً على الكود ويضيف المنتج للسلة.
   - خيار تعديل الكمية، السعر الخاص، أو تطبيق خصم بالمبلغ أو النسبة.
   - إتمام البيع مع تحديد طريقة الدفع: نقداً (مع حاسبة الباقي للعميل)، أو آجل (اختيار العميل وتحديث دينه)، أو تحويل بنكي.
   - شاشة فورية لنجاح البيع مع خيارات: معاينة الإيصال الحراري، مشاركته كـ PDF/صورة، أو بدء فاتورة جديدة.
2. **إدارة المخزون والمنتجات (Inventory)**:
   - قائمة بحث وفرز ذكية (الكل، وشكت على النفاد، منتهية الصلاحية، الأعلى ربحاً).
   - بطاقة منتج واضحة تحتوي على: اسم المنتج، الباركود، التصنيف، سعر الشراء، سعر البيع، هامش الربح، الكمية المتبقية، وتاريخ الصلاحية.
   - نموذج إضافة وتعديل مريح مع مولّد باركود تلقائي أو مسح بالكاميرا.
3. **دفتر الديون والعملاء (Customers & Debts)**:
   - قائمة العملاء مع إجمالي ديونهم باللون الأحمر أو المتوازن.
   - سجل مدفوعات العميل وتاريخ كل فاتورة آجلة مع زر سريع لتحصيل دفعة وتحديث الرصيد وطباعة سند قبض.
4. **الخزينة والتقارير المالية (Analytics & Cash Register)**:
   - بطاقات إحصائية رئيسية: إجمالي مبيعات اليوم، صافي الأرباح المحققة، النقد المتوفر بالصندوق، وإجمالي الديون في السوق.
   - رسم بياني لحركة المبيعات خلال الأسبوع، وقائمة بأكثر 5 منتجات مبيعاً.

### الهوية البصرية ونظام الألوان (Visual Identity & Theme)
- **الطابع العام**: تصميم عصري احترافي فائق الوضوح (Retail Modern Clean) يعتمد على التباين العالي والأزرار الواسعة الملائمة للعمل السريع.
- **دعم اللغة العربية والاتجاه (RTL Support)**: واجهات عربية أصيلة بنسبة 100% مع محاذاة من اليمين لليسار.
- **لوحة الألوان المعتمدة (Material 3 Tokens)**:
  - **اللون الأساسي (Primary)**: أخضر زمردي مالي `Color(0xFF0F766E)` يوحي بالنمو والموثوقية المالية.
  - **اللون الثانوي (Secondary)**: كحلي داكن موثوق `Color(0xFF1E293B)`.
  - **لون التمييز والأرباح (Accent / Success)**: أخضر عشبي مشرق `Color(0xFF16A34A)`.
  - **لون التنبيه والديون (Warning / Danger)**: أحمر ياقوتي `Color(0xFFDC2626)` لتنبيهات الصلاحية والديون غير المسددة.
  - **الخلفيات والأسطح (Surface & Background)**: رمادي فائق النعومة `Color(0xFFF8FAFC)` مع كروت بيضاء ناصعة `Color(0xFFFFFFFF)` وظلال خفيفة ناعمة.

## 3. القرارات التقنية والمفاضلات (Key Product Decisions)

1. **اعتماد قاعدة بيانات Room المحلية بالكامل**:
   - *الخيار المعتمد*: SQLite محلي عبر Room Database 2.7.0 مع KSP.
   - *السبب*: سرعة استجابة فائقة (أقل من 5 ميلي ثانية لكل عملية)، واستقلالية تامة عن الاتصال بالشبكة لضمان استمرار البيع دون توقف.
2. **محاكاة ودمج مسح الباركود الذكي**:
   - *الخيار المعتمد*: واجهة كاشير تدعم إدخال الباركود السريع وقارئ كاميرا مبسط مع دعم الأرقام التسلسلية المباشرة وحفظ أكواد EAN-13/UPC الشائعة في البقالات.
3. **تصميم الفاتورة الحرارية (Thermal Receipt Generator)**:
   - *الخيار المعتمد*: مكون عالي الدقة يولد فاتورة قياس 80 مم / 58 مم مع رأس المتجر، تاريخ ووقت العملية، رقم الفاتورة، جدول الأصناف، الإجماليات، رمز QR تجريبي للفاتورة، وتذييل شكر، مع قابلية الطباعة والمشاركة.
4. **تضمين بيانات تجريبية جاهزة (Seeded Demo Data)**:
   - *الخيار المعتمد*: تعبئة أولية لبقالة نموذجية (منتجات شائعة: حليب ممتاز، زبادي، أرز بسمتي، سكر، زيت نباتي، تونة، معكرونة، مياه، بسكويت) مع بعض العملاء، حتى يتمكن المستخدم من اختبار نقطة البيع والتقارير بمجرد فتح التطبيق.

### الكيانات وجداول البيانات (Room Entities)

1. **`Product`**:
   - `id`: Int (PrimaryKey)
   - `barcode`: String (Unique/Indexed)
   - `name`: String
   - `category`: String
   - `costPrice`: Double (سعر الشراء/التكلفة)
   - `sellPrice`: Double (سعر البيع)
   - `stockQuantity`: Double (الكمية المتوفرة)
   - `minStockAlert`: Double (الحد الأدنى للتنبيه)
   - `unit`: String (حبة، كرتون، كجم، لتر)
   - `expiryDate`: Long? (تاريخ الصلاحية)
2. **`SaleOrder`**:
   - `id`: Long (PrimaryKey)
   - `invoiceNumber`: String (رقم الفاتورة التلقائي مثل INV-2026-001)
   - `timestamp`: Long
   - `subtotal`: Double
   - `discountAmount`: Double
   - `totalAmount`: Double
   - `paymentType`: String (CASH, DEBT, TRANSFER)
   - `customerId`: Long? (مرتبط بالعميل إن كان بيعاً بالآجل)
   - `paidAmount`: Double
   - `remainingDebt`: Double
3. **`OrderItem`**:
   - `id`: Long (PrimaryKey)
   - `orderId`: Long
   - `productId`: Int
   - `productName`: String
   - `quantity`: Double
   - `unitPrice`: Double
   - `costPrice`: Double
   - `total`: Double
4. **`Customer`**:
   - `id`: Long (PrimaryKey)
   - `name`: String
   - `phone`: String
   - `currentDebt`: Double (إجمالي الدين المستحق عليه)
   - `notes`: String
5. **`CustomerPayment`**:
   - `id`: Long (PrimaryKey)
   - `customerId`: Long
   - `amount`: Double
   - `timestamp`: Long
   - `notes`: String
6. **`CashTransaction`**:
   - `id`: Long (PrimaryKey)
   - `type`: String (INCOME, EXPENSE, DEBT_COLLECTION)
   - `amount`: Double
   - `description`: String
   - `timestamp`: Long

## 5. خطة التنفيذ المعتمدة (Step-by-Step Implementation Steps)

1. **تحديث البيانات الوصفية (Metadata & Strings)**:
   - تسمية التطبيق بـ "نقاط البيع والمخزون | POS Pro" في `metadata.json` و`strings.xml`.
2. **بناء طبقة البيانات المحلية (Room Database & DAOs)**:
   - إنشاء الكيانات `Product`, `SaleOrder`, `OrderItem`, `Customer`, `CustomerPayment`, `CashTransaction`.
   - كتابة واجهات `ProductDao`, `OrderDao`, `CustomerDao`, `CashDao` مع استعلامات متقدمة لحساب الأرباح والديون.
   - إنشاء `AppDatabase` ومستودع البيانات الموحد `PosRepository` مع حقن البيانات الأولية التلقائية للبقالة.
3. **بناء منطق الأعمال وإدارة الحالة (ViewModel)**:
   - السلة الذكية: إضافة، تقليل، حذف، تطبيق الخصم، حساب الإجمالي بالريال اليمني.
   - عملية السداد الشاملة: خصم فوري من المخزون، تسجيل الفاتورة، تسجيل العملية في الصندوق، وإضافة الدين لحساب العميل إذا كان الدفع آجلاً.
4. **تطوير واجهات المستخدم التفاعلية (Jetpack Compose UI)**:
   - شريط التنقل السفلي الحديث (الكاشير، المخزون، العملاء والديون، الخزينة والتقارير).
   - واجهة الكاشير مع سلة جانبية/سفلية منبثقة، شبكة المنتجات، وفلتر الفئات السريع.
   - نافذة إتمام الدفع مع حاسبة الباقي واختيار العميل وسند البيع.
   - معاينة وطباعة الفاتورة الحرارية بنمط إيصالات المتاجر.
   - إدارة المخزون مع نموذج إضافة/تعديل وتنبيهات النقص والصلاحية.
   - دفتر العملاء وإدارة سداد الديون.
   - لوحة تحكم الخزينة مع تقارير الأرباح والمبيعات.
5. **التحقق والاختبار (Build Verification)**:
   - تشغيل `compile_applet` للتأكد من خلو المشروع من أي أخطاء ترجمة وسلامة عمل كافة الشاشات.
